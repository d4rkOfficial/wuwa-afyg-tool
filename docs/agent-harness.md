# AI 助手：Agent Harness

本文档描述 AI 助手的回合结构、上下文组成、变化队列与自定义 Skill。

> 相关源码
>
> | 文件                                            | 职责                                                                 |
> | ----------------------------------------------- | -------------------------------------------------------------------- |
> | `src/lib/ai/session.ts`                         | 回合循环、消息装配、事件分发（双协议：Responses / Chat Completions） |
> | `src/lib/ai/persona.ts`                         | 默认人设提示词                                                       |
> | `src/lib/ai/change-queue.svelte.ts`             | 工程变化队列                                                         |
> | `src/lib/data/ai-skills.svelte.ts`              | 自定义 Skill（技能卡）存储                                           |

## 1. 回合结构

一轮对话 = 一次 `runAiTurn()`，内部最多 `MAX_TOOL_ROUNDS = 8` 个工具轮次：

```
user 消息
  └─ for round in 0..8:
       调用模型（流式）
       ├─ 有工具调用 → 逐个 executeTool() → 结果回灌为 tool 消息 → 继续下一轮
       └─ 无工具调用 → 结束本轮
事件流（onEvent）：ai / reasoning / tool / confirm / error / done
```

`buildTools()` 返回全部已注册工具（见 [tools.md](./tools.md)）；危险工具在 `executeTool` 前经
`onConfirm` 走确认卡片，确认策略由设置里的 `dangerMode` 决定：

| 模式          | 行为                                   |
| ------------- | -------------------------------------- |
| `ask`（默认） | 每次危险操作都询问                     |
| `ask_once`    | 一次指令回合内只询问一次，之后自动放行 |
| `trust`       | 无条件信任，直接执行                   |

## 2. 上下文装配顺序

`runAiTurn` 组装的消息序列（顺序固定）：

1. `system` 人设提示词（用户自定义优先，清空回落默认）
2. `system` **技能清单** —— 只含「名称 + 一句话描述」，正文按需激活（省 token）
3. `system` **当前状态** —— 工程名/id、当前视图、四环节锁定态、打开的弹窗
4. `system` **变化队列** —— 自上次对话以来的工程改动
5. `history` 历史消息（含此前的工具调用与结果）
6. `user` 本轮用户消息

> 状态与变化都是「以本条为准」的强声明：模型被明确要求在与记忆冲突时以最新事实为准，需要细节时用工具重查。

## 3. 变化队列

`change-queue.svelte.ts` 把「切换工程」与「当前工程四阶段数据的任何变化」记录下来，在**下一轮**对话开头
以系统消息上报，避免用户改完状态后助手仍按旧记忆作答。

- 入队：`pushProjectSwitch()` / `pushPhaseChange(phase, detail)` / `pushTeamChange()`
- 合并：同 `kind` 且 1.5s 窗口内的连续变化合并为一条并累加 `×N`（连续拖拽数值不会刷屏）
- 上限：环形队列 50 条，超出丢弃最旧
- 消费：`drainChanges()` 在回合开始时取出并清空，同一条变化不会重复上报
- 界面：助手底部显示「已记录 N 条工程变化，将在下次提问时告知助手」，可一键「忽略」

指纹来源：`+page.svelte` 中对 `工程 id + 队伍 + 四阶段数据` 建立 `$effect` 指纹，
首次建立基线时不入队（避免刚打开页面就产生噪声）。

## 4. 自定义 Skill

技能卡 = 用户预置的**操作规范**，解决「同一套要求每次都要重复交代」的问题。

```ts
interface AiSkill {
    id: string
    name: string // 唯一，AI 通过它激活
    description: string // 一句话，注入清单供 AI 判断何时激活
    body: string // 激活后注入的完整正文
    enabled: boolean
    builtin?: boolean // 内置技能不可删除，可禁用 / 改正文
}
```

- 存储：IndexedDB `ai-skills`；内置技能在 `loadSkills()` 时与代码定义合并（保留用户对正文/启用的修改）
- 工具：`list_skills`（列出）、`use_skill(name)`（激活并返回正文；未找到时回传可用名称）
- **延迟注入**：清单只进名称与描述，正文只在被激活时进入上下文 —— 这是最主要的 token 优化
- 内置技能两张：
    - **数据自愈** —— 查询类工具返回空/异常时，按 team → timeline → calculation → config 重载后重试
    - **条件与链阶** —— 条件挂在乘区（伤害类型/属性）、链阶是整块硬性条件且互斥、链阶真源是角色槽位
- 界面：助手头部 ⚡ 面板（启用开关 / 新建 / 编辑 / 删除 / 导入导出 JSON），输入框上方快捷 chip 点击即把
  指令前缀写入输入框；导出格式为 `{ kind: 'wuwa-afyg-skills', skills: [...] }`

## 5. 界面结构

助手是一个可拖拽悬浮窗（收起圆钮 / 小卡片 / 全尺寸三态）：

| 区域       | 内容                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------- |
| 头部       | 当前模型与提供方、技能面板开关、清空对话、尺寸切换                                       |
| 消息区     | 每条助手消息按「聊天 / 思考 / 工具」分 tab；工具调用以时间线列出（名称、参数、结果长度） |
| 变化队列条 | 待上报变化数量与「忽略」                                                                 |
| 技能面板   | 技能卡列表与编辑器                                                                       |
| 输入区     | 快捷技能 chip + 文本域（Enter 发送 / Shift+Enter 换行；生成中变停止按钮）                |
| 危险确认   | 内联卡片（不遮罩），显示工具名与参数摘要，允许 / 拒绝                                    |
