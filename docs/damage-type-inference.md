# 伤害类型推导算法与 TDD 用例流程

本文档说明「伤害条目 → 伤害类型」的自动推导链（`src/lib/calc/skill-infer.ts` + `src/lib/calc/utils.ts`），
以及如何用 `assertCorrectDamageTypeInfer` 以 TDD 方式给推导算法补用例、定位与修护栏。

## 一、输入与输出

| 项           | 内容                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 输入         | 伤害条目（`DamageEntry`）：`skillType`（技能类型）、`hitName`（倍率行名）、`isEffect`（是否效应结算） |
| 附加输入     | 声骸技能条目的首位声骸文案（应用层通过 `buildEchoDescByEntry` 传入）；用户手动设置的伤害类型          |
| 输出         | `DAMAGE_TYPES` 之一（`src/lib/consts/game-terms.ts`）                                                 |
| 入口         | `inferDamageTypes(entry, charInfo, echoDesc?)`（`src/lib/calc/utils.ts`）                             |
| 应用层优先级 | 用户手动设置的类型不会被自动推导覆盖                                                                  |

`DAMAGE_TYPES`：普攻伤害 / 重击伤害 / 共鸣技能伤害 / 共鸣解放伤害 / 声骸技能伤害 / 变奏技能伤害 /
延奏技能伤害 / 协同攻击伤害 / 效应伤害 / 其它类型伤害。

## 二、判定链（优先级从高到低）

| #   | 规则              | 判定方式                                                                                                                     | 例                                           |
| --- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 1   | 效应结算          | `entry.isEffect` → 效应伤害（不看文案）                                                                                      | 效应结算条目                                 |
| 2   | 规则2：技能文案   | 在该倍率**所属技能节点**的富文本里找「视为/为 XX 伤害」；分「大标题小节定位 → 两轮匹配 → 三种结论定位」三层（见下）          | 长离 共鸣回路「重击·焚身以火」→ 共鸣技能伤害 |
| 3   | 规则1：倍率名前缀 | 倍率名含 `普攻·` / `重击·` / `空中攻击` / `闪避反击` / `共鸣技能·` / `共鸣解放·` / `变奏技能·` / `延奏技能·`                 | 「重击·炼羽裁决第一段伤害」→ 重击伤害        |
| 4   | 技能类型兜底      | 常态攻击：名含「重击」→ 重击伤害，否则普攻伤害；共鸣技能/共鸣解放/声骸技能/变奏技能/延奏技能 → 同名伤害；其余 → 其它类型伤害 | 共鸣回路里的冷门行 → 其它类型伤害            |

规则1 中 **空中攻击 / 闪避反击默认按普攻伤害结算**（它们属普攻体系），文案写明「为重击伤害」的由规则2 覆盖。

## 三、规则2 详解

### 3.1 只在该倍率所属技能节点里找

`inferFromSkillText` 只用「技能类型 + 行名都对得上」的节点文案；找不到才退到同技能类型的节点，最后才用调用方
额外提供的声骸文案。**绝不跨节点搜索**——否则别的小节里的同类词会把结论错误地锚到本行：

> 长离 常态攻击的「重击」曾被共鸣回路的「施放重击时…此次伤害为共鸣技能伤害」带成共鸣技能伤害。

### 3.2 定位到具体大标题小节

上游富文本用小节标题（`<color=Title>重击</color>`）分隔技能内部小节。`sectionTextsForHit` 按可信度返回候选小节：

1. **标题名与倍率名互相包含**（标题「重击」↔ 倍率「重击」、标题「普攻·预求身」↔ 倍率「普攻·预求身第二段伤害」），
   标题越长越具体排在前；
2. **小节正文里出现该倍率名**（如「热压弹伤害」的结论写在「共鸣技能·咔咔压制」小节里，而标题「热压弹获取规则」只是资源规则）。

约定：

- 有候选小节时**只在小节内找结论**，一个小节都没结论也不回退整段（回退会把别的小节的结论抄过来）；
- 没有任何小节提到该倍率、或文案压根没有大标题时，才按整段匹配（与历史行为一致）。

### 3.3 小节内的两轮匹配

| 轮次   | 认什么   | 说明                                                                                                      |
| ------ | -------- | --------------------------------------------------------------------------------------------------------- |
| 第一轮 | 明写结论 | 「视为/视作/算作/计为/为 XX 伤害」句式（含「XX效应」）；分同句锚定与归属兜底两种定位                      |
| 第二轮 | 名称徽标 | 倍率名紧跟在「XX 技能 / XX【」之后（「共鸣技能【雾化子弹】」「共鸣技能飞身式·翻山越涧」「普攻烬华蔓舞」） |

明写结论必须优先于徽标：交叉引用里的类型词会骗人——今汐文案「施放普攻凌霄·普攻第4段后…」里的「普攻」属于**被引用
技能名**，而该技能自己写着「此次伤害为共鸣技能伤害」。

两轮内部各自的三种定位：

1. **同句锚定**：结论句里同时出现本行技能名关键词；纯段号关键词还要求同句出现技能名（挡掉「第3段为空中下落攻击」这类旁述）；
2. **名称徽标**：见上表；徽标类型词口径与规则1 一致（空中攻击/闪避反击 → 普攻伤害）；
3. **归属兜底**：结论归属于它前面最近的倍率行名/小节头；所属是「本行 / 本节 / 前面没有行名」才采纳；结论句写明段号时必须含本段号；
   去掉这些后若仍存在多个不同伤害类型则视为歧义，放弃（交给规则1/兜底）。

### 3.4 护栏清单（每条都对应一个真实错例）

| 护栏                                   | 挡住的错误                         | 真实案例                                                       |
| -------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| 不跨技能节点搜索                       | 别的节点的同类词把结论锚过来       | 长离 常态攻击「重击」→ 曾被推成共鸣技能伤害                    |
| 关键词要成词，子串不算                 | 「技能伤害」被「共鸣技能伤害」吃掉 | 长离/安可 等的「共鸣解放伤害」「变奏技能伤害」行               |
| 裸动作词（普攻/重击…）不作关键词       | 别的小节认领裸词                   | 秧秧·玄翎 常态攻击「普攻·苍剑式」各段                          |
| 段号冲突只按本分句判断                 | 邻段结论套到本段                   | 嘉贝莉娜「重击·炼羽裁决」第 1/2 段                             |
| 徽标要避开标题粘连                     | 标题里的小节名被当成本行徽标       | 琳奈「绮彩巡游·普攻」系列曾被「绮彩巡游·地面重击」标题推成重击 |
| 同族短名不抢归属                       | 「强光」⊂「强光穿射每段」          | 灯灯「强光穿射每段伤害」                                       |
| 明写结论优先于徽标                     | 交叉引用里的类型词混淆判定         | 今汐「凌霄·普攻」                                              |
| 本行行名（含去段号的小节头名）参与归属 | 整节共用一句结论时归属丢失         | 绯雪「普攻·预求身」各段（结论只写在小节开头）                  |

### 3.5 行名从哪来（写用例前必读）

推导用的是**面板行名**，即 `SkillEntry.values[0]`，它已被上游转换层规范化：

- 上游 `preprocessSkills` 会把「技能伤害」按技能类型改写成 `共鸣技能伤害` / `变奏技能伤害` / `共鸣解放伤害` / `延奏技能伤害`，
  把常态攻击的「第N段伤害」改写成「常态攻击第N段伤害」；
- `makeSkillValues` 会丢掉**没有数值的纯说明行**（这类行不参与拉表，也就不需要断言）。

所以用例里的 `ratioName` 必须用面板里的写法，别照抄上游原始 JSON 的行名。**先跑 `listRatios` 核对**。

## 四、TDD 流程

1. **查行名**：`await listRatios('长离', '重击')`（或直接看游戏面板），拿到精确行名；
2. **写期望（先红）**：复制空白模板
   [`scripts/test/damage-type-infer.example.ts`](../scripts/test/damage-type-infer.example.ts) 为你的用例脚本，
   把「角色 + 行名 + 期望伤害类型」填进 `CASES`。期望值只能来自**游戏内伤害类型判定**或**文案明写**，不许凭空猜；
3. **跑**：
    ```bash
    node --import ./scripts/test/preload.mjs scripts/test/damage-type-infer.example.ts
    ```
    失败会打印 `期望 X，实际 Y（命中节点：…）`，并以非 0 退出码结束；
4. **定位**：先确认期望值本身没错，再看算法。需要看原文时：
    ```ts
    await dumpRatioContext('长离', '重击') // 打印该倍率相关技能文案，大标题单独成行
    ```
    对照「结论写在哪一节」「本行名字出现在哪」判断该由哪条护栏负责；
5. **改算法**：只改 `src/lib/calc/skill-infer.ts`（规则2）或 `src/lib/calc/utils.ts`（兜底），不要为了让用例变绿改期望值；
6. **跑绿**：重跑第 3 步；
7. **固化**：
    - 依赖网络/上游文案的用例留在 `scripts/test/` 下（不进 `pnpm test` 聚合入口）；
    - 结构性行为补进**离线夹具** `src/lib/calc/skill-infer.test.ts`（自带文案 fixture，不联网），
      一条护栏至少一条离线用例；
8. **收尾**：`pnpm run format && pnpm run lint:eslint && pnpm run check`。

### 4.1 离线夹具长什么样

```ts
const skills: RawSkill[] = [
    { type: '常态攻击', desc: '<size=40><color=Title>重击</color></size>长按普攻…', rows: ['重击'] }
]
assert.equal(typeOf('常态攻击', '重击', skills), '重击伤害')
```

`RawSkill` 的 `desc` 要保留 `<color=Title>` 标记（推导按它切小节），`rows` 就是面板行名。

### 4.2 从 bug 报告到用例（三步）

收到「某角色某倍率类型推错了」时：

1. 把报告转成期望值：查行名 → 写一条用例（`note` 里贴报告原文），先确认它**红**；
2. 让红变绿：`dumpRatioContext` 看文案落点，判断该补哪条护栏，改 `skill-infer.ts`；
3. 固化：为这条护栏补一条**离线**用例（不联网、跑得快），并跑一次全角色普查确认没误伤别人。

## 五、让 AI 生成用例脚本

### 5.1 提示词模板

```text
请为「伤害类型推导」写 TDD 用例脚本，只写用例，不要改算法。
角色：<角色名>

要求：
1. 以 scripts/test/damage-type-infer.example.ts 为模板，用例文件写到 scripts/test/damage-type-infer.<角色>.ts；
2. 覆盖该角色全部技能节点的伤害行：先调用 listRatios('<角色名>') 拿精确行名，不要凭印象写行名；
3. expectedDamageType 只能来自「游戏内伤害类型判定」或文案明写的「此次伤害为 XX 伤害」；
   两者都没有时按判定链兜底（规则1 前缀 → 技能类型），并在 note 里写明依据；
4. 行名在多个技能节点里重名时必须带 skillType；
5. 每条用例写 note，注明依据（哪句话 / 哪条规则）；
6. 交付物：用例脚本 + `node --import ./scripts/test/preload.mjs <文件>` 的真实输出（红/绿）+ 失败项分析
   （区分「期望值写错」与「算法缺护栏」）。
```

### 5.2 验收标准（AI 交付必须满足）

- 脚本能直接跑：`node --import ./scripts/test/preload.mjs scripts/test/<文件>.ts`（**必须带 preload**，它解析 `$lib` 别名与无扩展名导入）；
- 行名全部来自 `listRatios`，无「按印象猜」的行名；重名行都带了 `skillType`；
- 期望值可追溯：要么是游戏内判定，要么能在文案里指出原句；
- 若需改算法：说明改的是哪条护栏、为什么不会误伤别的小节，并给出全角色普查的前后对比结论（见第六节）；
- 不允许为了让用例变绿而放宽期望值或删用例。

## 六、批量普查（改算法后防回归）

改动规则2 这类「全局生效」的护栏后，用普查脚本对比改前改后：

```ts
import { getProvider } from '$lib/api/provider'
import { sweepDamageTypeInfer } from './damage-type-infer'

await sweepDamageTypeInfer(['长离', '安可', '嘉贝莉娜']) // 也可跑全量角色
const names = (await getProvider().getCharacterList()).map((character) => character.name)
await sweepDamageTypeInfer(names)
```

输出 `角色 | 技能类型 | 行名 → 推导类型`。做法：改动前后各跑一次存成文件 → diff → **逐行**确认每处变化都是修正
（对照上游原文，判断结论该落在哪一节）。上一轮长离修复就是这样验证的：64 角色 1309 行中 113 行变化，逐条核对后
确认全部为修正（多为「变奏技能/共鸣解放」误推成共鸣技能伤害一类）。

## 七、常见失败与排查

| 症状                               | 原因                                               | 处理                                                             |
| ---------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| 「没有倍率行 X」                   | 行名写法与面板不一致；或该行没有数值被上游转换丢弃 | `listRatios(角色, 关键字)` 核对；纯说明行不参与推导，不必断言    |
| 「在多个技能节点里推导结果不一致」 | 行名重名（如「技能伤害」类、通用名）               | 用例补 `skillType`                                               |
| 期望值与文案不符                   | 结论写在**别的技能**的小节里                       | 按「倍率来自哪个技能就只找哪个技能」修正期望值（别改算法去迁就） |
| 期望值报「不是合法伤害类型」       | 期望值用了短名（普攻）或非法串                     | 用完整名（普攻伤害），或在用例里定义本地短名枚举                 |
| 结果恰好等于「其它类型伤害」       | 规则2/规则1 都没命中，落到兜底                     | 若文案确有结论 → 算法缺护栏；若确实没有 → 期望值就该是它         |
| 上游改版后用例红                   | 行名或文案变化                                     | 以面板/文案为准更新用例；必要时补护栏                            |

### 夹具 API 速查

| API                                                         | 用途                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------ |
| `assertCorrectDamageTypeInfer(角色, 行名, 期望类型, 选项?)` | 单条断言；失败信息带实际值、命中节点与排查入口         |
| `reportDamageTypeInfer(用例数组, 标题?)`                    | 批量跑用例并汇总；有失败则抛错（退出码非 0）           |
| `inferDamageTypeOf(角色, 行名, 选项?)`                      | 只返回推导结果，不抛断言错误（排查、普查用）           |
| `listRatios(角色, 关键字?)`                                 | 打印/返回该角色的面板行名                              |
| `dumpRatioContext(角色, 行名, 选项?)`                       | 打印相关技能文案（大标题单独成行），判断结论落在哪一节 |
| `sweepDamageTypeInfer(角色数组)`                            | 逐行普查，用于改前改后 diff                            |
| `assertDamageTypeEnum(本地短名枚举)`                        | 自检本地枚举值是否都在权威清单里                       |

选项（`InferCase` 字段）：`skillType`（行名重名时定位）、`isEffect`（效应结算）、`note`（依据，失败报告里打印）。
