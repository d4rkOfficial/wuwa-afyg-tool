# 伤害类型推导与 TDD 流程

说明「伤害条目 → 伤害类型」的自动推导链（`src/coconut-core/engine/skill-infer.ts` + `engine/utils.ts`），以及用 `assertCorrectDamageTypeInfer` 以 TDD 补用例、定位与修护栏。

## 输入与输出

| 项           | 内容                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------- |
| 输入         | `DamageEntry`：`skillType`（技能类型）、`hitName`（倍率行名）、`isEffect`（是否效应）           |
| 附加输入     | 声骸技能条目首位声骸文案（应用层 `buildEchoDescByEntry` 传入）；用户手动设置的伤害类型          |
| 输出         | `DAMAGE_TYPES` 的一个或多个（`string[]`；「同时视为」产出双类型，如 `['重击伤害','效应伤害']`） |
| 入口         | `inferDamageTypes(entry, charInfo, echoDesc?)`（`engine/utils.ts`）                             |
| 应用层优先级 | 用户手动设置的类型不被自动推导覆盖                                                              |

`DAMAGE_TYPES`：普攻 / 重击 / 共鸣技能 / 共鸣解放 / 声骸技能 / 变奏技能 / 延奏技能 / 协同攻击 / 效应 / 其它类型伤害。

## 判定链

优先级从高到低：

| #   | 规则              | 判定方式                                                                                                                 | 例                                           |
| --- | ----------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| 1   | 效应结算          | `entry.isEffect` → 效应伤害（不看文案）                                                                                  | 效应结算条目                                 |
| 2   | 规则2：技能文案   | 在该倍率**所属技能节点**富文本里找「视为/为 XX 伤害」；分「大标题小节定位 → 两轮匹配 → 三种结论定位」三层（见「规则2」） | 长离 共鸣回路「重击·焚身以火」→ 共鸣技能伤害 |
| 3   | 规则1：倍率名前缀 | 倍率名含 `普攻·`/`重击·`/`空中攻击`/`闪避反击`/`共鸣技能·`/`共鸣解放·`/`变奏技能·`/`延奏技能·`                           | 「重击·炼羽裁决第一段伤害」→ 重击伤害        |
| 4   | 技能类型兜底      | 常态攻击：名含「重击」→ 重击伤害，否则普攻；共鸣技能/解放/声骸/变奏/延奏 → 同名伤害；其余 → 其它类型                     | 共鸣回路冷门行 → 其它类型伤害                |

| 附加规则 | 说明                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 普攻体系 | 空中攻击 / 闪避反击默认按普攻伤害结算；文案写明「为重击伤害」的由规则2 覆盖 |
| 同时视为 | 追加类型：主类型按普通结论/规则1/技能类型取，再把同时类型并进结果           |

「同时视为」示例：

| 文案                                             | 结果                                     |
| ------------------------------------------------ | ---------------------------------------- |
| 「此次伤害为重击伤害，同时视为【光噪效应】伤害」 | 重击伤害 + 效应伤害                      |
| 「造成气动伤害，同时视为【风蚀效应】伤害」       | 主类型取规则1（空中攻击→普攻）+ 效应伤害 |

## 规则2：技能文案

### 节点定位

`inferFromSkillText` 只用「技能类型 + 行名都对得上」的节点文案；找不到才退到同技能类型节点，最后用调用方额外提供的声骸文案。**不跨节点搜索**——别的小节的同类词会把结论错误锚到本行。

> 长离常态攻击的「重击」跨节点搜索，会被共鸣回路「施放重击时…此次伤害为共鸣技能伤害」带成共鸣技能伤害。

### 小节定位

上游富文本用小节标题（`<color=Title>重击</color>`）分隔技能内部小节。`sectionTextsForHit` 按可信度返回候选：

| 优先 | 依据                         | 例                                                                  |
| ---- | ---------------------------- | ------------------------------------------------------------------- |
| 1    | 标题名与倍率名互相包含       | 标题「重击」↔ 倍率「重击」；标题越长越具体排前                      |
| 2    | 小节正文里出现该倍率名       | 「热压弹伤害」结论写在「共鸣技能·咔咔压制」小节，而标题只是资源规则 |
| 3    | 倍率是正文【部件名】的派生行 | 「冰川爆炸伤害」↔【冰川】；「冰绽」小节写明其伤害为共鸣技能伤害     |
| 4    | 动作派生行以小节头动作名开头 | 「空中攻击回收一剑」↔「空中攻击·卡提希娅」小节                      |

约定：有候选小节时只在小节内找结论，一个小节都没结论也不回退整段；没有任何小节提到该倍率、或文案无大标题时，才按整段匹配。

### 两轮匹配

| 轮次   | 认什么   | 说明                                                                                       |
| ------ | -------- | ------------------------------------------------------------------------------------------ |
| 第一轮 | 明写结论 | 「视为/视作/算作/计为/为 XX 伤害」句式（含「XX效应」「【XX效应】」）；分同句锚定与归属兜底 |
| 第二轮 | 名称徽标 | 倍率名紧跟「XX 技能 / XX【」之后（「共鸣技能【雾化子弹】」「普攻烬华蔓舞」）               |

明写结论优先于徽标：交叉引用里的类型词会骗人——今汐文案「施放普攻凌霄·普攻第4段后…」里的「普攻」属**被引用技能名**，而该技能自己写着「此次伤害为共鸣技能伤害」。

第一轮带「同时」前缀的结论不顶替主类型，作为追加类型返回；追加类型只在**主类型所在小节**找，避免串入别的小节（绯雪「霜冻效应」小节）。

三种结论定位（两轮内部各自）：

| 定位     | 规则                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 同句锚定 | 结论句里同时出现本行技能名关键词；纯段号关键词还要求同句出现技能名（挡掉「第3段为空中下落攻击」这类旁述）                                                   |
| 名称徽标 | 见上表；徽标类型词与规则1 一致（空中攻击/闪避反击 → 普攻伤害）                                                                                              |
| 归属兜底 | 结论归属于前面最近的倍率行名/小节头；所属是「本行/本节/前面没有行名」才采纳；写明段号时必须含本段号；去掉后仍有多个不同类型则视为歧义，放弃（交规则1/兜底） |

部件派生行（「冰川爆炸伤害」↔【冰川】）用部件名参与第一轮同句锚定：正文「…引爆【冰棘】、【冰棱】和【冰川】…冰绽造成的伤害为共鸣技能伤害」同句含【冰川】与结论，故归共鸣技能伤害。资源/状态名不算部件（「暗流·普攻」里的「暗流」），前缀后紧跟 `·` 等分隔符时不参与部件锚定。

### 护栏清单

每条对应一个真实错例：

| 护栏                                 | 挡住的错误                             | 真实案例                                                 |
| ------------------------------------ | -------------------------------------- | -------------------------------------------------------- |
| 不跨技能节点搜索                     | 别的节点同类词把结论锚过来             | 长离常态攻击「重击」→ 跨节点被推成共鸣技能伤害           |
| 关键词要成词，子串不算               | 「技能伤害」被「共鸣技能伤害」吃掉     | 长离/安可的「共鸣解放伤害」「变奏技能伤害」行            |
| 裸动作词（普攻/重击…）不作关键词     | 别的小节认领裸词                       | 秧秧·玄翎常态攻击「普攻·苍剑式」各段                     |
| 段号冲突只按本分句判断               | 邻段结论套到本段                       | 嘉贝莉娜「重击·炼羽裁决」第 1/2 段                       |
| 徽标要避开标题粘连                   | 标题里的小节名当成本行徽标             | 琳奈「绮彩巡游·普攻」→ 被「绮彩巡游·地面重击」推成重击   |
| 同族短名不抢归属                     | 「强光」⊂「强光穿射每段」              | 灯灯「强光穿射每段伤害」                                 |
| 明写结论优先于徽标                   | 交叉引用里的类型词混淆判定             | 今汐「凌霄·普攻」                                        |
| 本行行名（含去段号小节头名）参与归属 | 整节共用一句结论时归属丢失             | 绯雪「普攻·预求身」各段                                  |
| 部件派生行按【部件名】锚定           | 行名接不上小节名导致落兜底             | 散华「冰川/冰棱/冰棘爆炸伤害」→ 共鸣技能伤害（冰绽小节） |
| 「A 替换为 B」时 B 继承 A 的结论     | 换形技能不重复写伤害类型               | 心「重击·应世相/照世相·镇红尘/镇寰宇」→ 共鸣技能伤害     |
| 【XX效应】括号写法参与匹配           | 「同时视为【风蚀效应】伤害」整句漏匹配 | 卡提希娅「空中攻击」、赞妮「重斩」系列                   |
| 「同时视为」产出双类型               | 追加类型被当成唯一类型或丢失           | 卡提希娅「空中攻击」→ 普攻+效应；赞妮「重斩」→ 重击+效应 |
| 追加类型只在主类型所在小节找         | 候选小节里的追加结论串到本行           | 绯雪「普攻·居合」不被「霜冻效应」小节追加效应            |
| 动作派生行按小节头动作名归属         | 「空中攻击回收一剑」接不上完整行名     | 卡提希娅「空中攻击回收一/二/三剑」                       |

### 行名来源

推导用**面板行名**，即 `SkillEntry.values[0]`，已被上游转换层规范化：

| 转换               | 说明                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `preprocessSkills` | 「技能伤害」按技能类型改写成 `共鸣技能伤害`/`变奏技能伤害`/`共鸣解放伤害`/`延奏技能伤害`；常态攻击「第N段伤害」改写为「常态攻击第N段伤害」 |
| `makeSkillValues`  | 丢掉没有数值的纯说明行（不参与拉表，无需断言）                                                                                             |

用例里的 `ratioName` 必须用面板写法，先跑 `listRatios` 核对。

## TDD 流程

| 步  | 操作                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 查行名：`await listRatios('长离', '重击')`（或看游戏面板）                                                                                                                      |
| 2   | 写期望（先红）：复制 `test/damage-type-infer.example.ts` 为用例脚本，填「角色 + 行名 + 期望类型」进 `CASES`；期望只能来自游戏内判定或文案明写                                   |
| 3   | 跑：`node --import ./test/preload.mjs test/damage-type-infer.example.ts`；失败打印「期望 X，实际 Y（命中节点：…）」并非 0 退出                                                  |
| 4   | 定位：先确认期望没错；`await dumpRatioContext('长离', '重击')` 打印该倍率相关文案，判断结论落在哪节                                                                             |
| 5   | 改算法：只改 `skill-infer.ts`（规则2）或 `engine/utils.ts`（兜底），不为让用例变绿改期望                                                                                        |
| 6   | 跑绿：重跑第 3 步                                                                                                                                                               |
| 7   | 固化：网络/上游用例留 `test/` 下用 `.ts`（不叫 `*.test.ts`，不进 `pnpm test`）；结构性行为补进离线夹具 `test/src/coconut-core/engine/skill-infer.test.ts`（自动跑到，无需登记） |
| 8   | 收尾：`pnpm run format && pnpm run lint:eslint && pnpm run check`                                                                                                               |

离线夹具示例：

```ts
const skills: RawSkill[] = [
    { type: '常态攻击', desc: '<size=40><color=Title>重击</color></size>长按普攻…', rows: ['重击'] }
]
assert.equal(typeOf('常态攻击', '重击', skills), '重击伤害')
```

`desc` 保留 `<color=Title>` 标记（推导按它切小节），`rows` 就是面板行名。

从 bug 报告到用例：

| 步  | 操作                                                                       |
| --- | -------------------------------------------------------------------------- |
| 1   | 报告转期望：查行名 → 写用例（`note` 贴报告原文），先确认红                 |
| 2   | 红变绿：`dumpRatioContext` 看文案落点，判断补哪条护栏，改 `skill-infer.ts` |
| 3   | 固化：补离线用例，跑一次全角色普查确认没误伤                               |

## 让 AI 生成用例

提示词模板：

```text

角色：<角色名>

要求：
1. 以 test/damage-type-infer.example.ts 为模板，用例文件写到 test/damage-type-infer.<角色>.ts；
2. 覆盖该角色全部技能节点的伤害行：先调用 listRatios('<角色名>') 拿精确行名，不要凭印象写；
3. expectedDamageType 只能来自「游戏内伤害类型判定」或文案明写的「此次伤害为 XX 伤害」；
   两者都没有时按判定链兜底（规则1 前缀 → 技能类型），并在 note 写明依据；
4. 行名在多个技能节点重名时必须带 skillType；
5. 每条用例写 note，注明依据（哪句话 / 哪条规则）；
6. 交付物：用例脚本 + `node --import ./test/preload.mjs <文件>` 的真实输出（红/绿）+ 失败项分析
   （区分「期望值写错」与「算法缺护栏」）。
```

验收标准：

| #   | 验收标准                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------- |
| 1   | 脚本能直接跑：`node --import ./test/preload.mjs test/<文件>.ts`（**必须带 preload**，解析 `$lib` 别名） |
| 2   | 行名全部来自 `listRatios`，无印象行名；重名行都带 `skillType`                                           |
| 3   | 期望值可追溯：游戏内判定或文案原句                                                                      |
| 4   | 改算法则说明改哪条护栏、为何不误伤别的小节，并给出全角色普查前后对比                                    |
| 5   | 不放宽期望值或删用例来让用例变绿                                                                        |

## 批量普查

改动规则2 这类全局护栏后，对比改前改后：

```ts
import { getProvider } from '$lib/api/provider'
import { sweepDamageTypeInfer } from './damage-type-infer'

const names = (await getProvider().getCharacterList()).map((character) => character.name)
await sweepDamageTypeInfer(names) // 也可只跑 ['长离', '安可', '嘉贝莉娜']
```

输出 `角色 | 技能类型 | 行名 → 推导类型`。做法：改前改后各跑一次存文件 → diff → 逐行确认每处变化都是修正（对照上游原文判断结论落点）。一次 64 角色 1309 行普查：113 行变化，逐条核对后全部为修正。

## 常见失败与排查

| 症状                               | 原因                                     | 处理                                                          |
| ---------------------------------- | ---------------------------------------- | ------------------------------------------------------------- |
| 「没有倍率行 X」                   | 行名写法与面板不一致；或该行无数值被丢弃 | `listRatios(角色, 关键字)` 核对；纯说明行不参与推导，不必断言 |
| 「在多个技能节点里推导结果不一致」 | 行名重名（「技能伤害」类、通用名）       | 用例补 `skillType`                                            |
| 期望值与文案不符                   | 结论写在**别的技能**小节里               | 按「倍率来自哪个技能就只找哪个技能」修正期望值                |
| 期望值报「不是合法伤害类型」       | 期望值用短名（普攻）或非法串             | 用完整名（普攻伤害），或定义本地短名枚举                      |
| 结果恰好等于「其它类型伤害」       | 规则2/规则1 都没命中，落兜底             | 文案确有结论 → 算法缺护栏；确实没有 → 期望值就该是它          |
| 上游改版后用例红                   | 行名或文案变化                           | 以面板/文案为准更新用例；必要时补护栏                         |

夹具 API：

| API                                                         | 用途                                             |
| ----------------------------------------------------------- | ------------------------------------------------ |
| `assertCorrectDamageTypeInfer(角色, 行名, 期望类型, 选项?)` | 单条断言；失败信息带实际值、命中节点与排查入口   |
| `reportDamageTypeInfer(用例数组, 标题?)`                    | 批量跑并汇总；有失败则抛错                       |
| `inferDamageTypeOf(角色, 行名, 选项?)`                      | 只返回推导结果，不抛断言（排查、普查）           |
| `listRatios(角色, 关键字?)`                                 | 打印/返回面板行名                                |
| `dumpRatioContext(角色, 行名, 选项?)`                       | 打印相关文案（大标题单独成行），判断结论落在哪节 |
| `sweepDamageTypeInfer(角色数组)`                            | 逐行普查，用于改前改后 diff                      |
| `assertDamageTypeEnum(本地短名枚举)`                        | 自检本地枚举值都在权威清单里                     |

`InferCase` 选项字段：`skillType`（行名重名定位）、`isEffect`（效应）、`note`（依据，失败报告打印）。
